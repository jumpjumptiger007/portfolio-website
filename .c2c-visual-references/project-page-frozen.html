01 PROJECT OVERVIEW

A receiver for internet discovery.

InterDemTV is structured as a project article: project context first, followed by the system, implementation, workflow, and observable controls.

InterDemTV turns a refreshed catalog of internet video into a constrained, television-like mode of discovery. Instead of search or a category browser, the interface asks a viewer to surf through a shuffled sequence of channels.

A retro CRT television, signal-room scene, and physical-style remote frame the experience. Viewers move forward or backward through the receiver sequence, then save a channel or permanently skip it in their own browser. Its core remains channel surfing and internet discovery.

At a glance

  • FormatStatic web experiment with a generated media catalog.
  • InteractionShuffle, tune, save, skip — a small but deliberate set of controls.
  • RoleA web experiment focused on constrained internet discovery and channel surfing.

03 IMPLEMENTATION

A static receiver with local state.

The receiver remains a static web application with generated catalog data, local browser state, and lightweight client-side behavior.

The application is static HTML, CSS, and JavaScript on GitHub Pages. A daily workflow collects a curated source set through Reddit RSS and Arctic Shift, produces a catalog of unique YouTube IDs, and can check that IDs are public and embeddable before the catalog is published.

At load, the receiver Fisher–Yates shuffles the catalog, then traverses that sequence forward or backward while skipping locally blocked IDs and playback failures. Favorites, permanent skips, and receiver settings persist in localStorage.

Playback positions are held only for the current page session. A service worker caches first-party static assets; YouTube playback remains outside that cache.

Implementation notes

  • DeploymentStatic site / GitHub Pages compatible.
  • StateFavorites, skips, and interface state stored locally.
  • Non-goalNo account system, no cloud sync, no recommendation engine.

04 VIEWER WORKFLOW

Tune, move, keep, or reject.

The viewer workflow is intentionally small: power on, move through channels, change signal behavior, then keep or reject a channel.

01

Power on

Load the shuffled receiver sequence and tune the current saved channel when one exists.

02

Move

Go forward or backward through the shuffled list; blocked and failed videos are left out of the sequence.

03

Change

Use RND to enter longer videos at a different point, or FILTER to turn CRT display effects on or off.

04

Keep / reject

Save a favorite or permanently skip an unwanted channel. Both choices remain local to the browser.

05 RECEIVER CONTROLS

A small set of deliberate controls.

The receiver exposes a compact set of controls for navigation, signal behavior, local memory, state restoration, and viewing.

Channel navigation

Previous and next travel through one shuffled receiver sequence.

Signal controls

RND changes the start point inside longer videos; FILTER changes CRT display effects only.

Local memory

Favorites and permanent skips are stored in the browser, without accounts or cloud sync.

Receiver state

Saved channel, volume, mute state, random mode, and ambience return across sessions.

Viewing

Fullscreen, a help modal, and keyboard shortcuts support the receiver interface.
